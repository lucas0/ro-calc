How to use RO Tools — Refine Calculator + MVP Tracker

A two-in-one Ragnarok Online toolkit: a refining-success calculator on the front page, and a multi-player MVP timer / loot / payment tracker at /mvp with optional Discord integration. This page explains how to use everything. Use the top bar to switch tools or toggle theme.

🔧 Refine Calculator

Compute the best path to +N on any piece of equipment given your supplies (ores, blessings, protection). Output: success probability, expected cost, and a recommended sequence.

Quick start

1
Pick server type in the top bar (Type dropdown):
  • Pre-Renewal — classic mechanics, no Blessings, no Enriched Bradium.
  • Renewal — modern official; HD ores, Blessings, Enriched.
  • Hercules — common private-server tweaks.
The choice is shared with the MVP Tracker and persists across sessions.
2
Set the equipment. Pick the item slot (Weapon / Armour / Headgear / Garment / Footwear / Shield / Accessory) and current refine level.
3
Set the target refine. The calculator shows the chance for each successive step plus the recommended ore / protection combo.
4
Add costs. Type in prices (e.g. 500k, 5m) for each ore and the calculator estimates total expected zeny to reach target. The cheaper-path bar shows where you save most.
Tip — shorthand input. Anywhere you see a zeny field you can type 5k (5,000) / 5m (5,000,000) / 5b (5,000,000,000). Decimals are fine: 1.5m.

Reading the result

CellMeaning
Safe (green)You're below the break threshold; failure refunds your protection / does no damage.
Risky (red)Failure breaks the item without protection.
Start / TargetYour current and target refine levels; the calculator highlights the recommended drop-back level if you fail.
Profit barsPer-attempt expected zeny relative to selling at +N. Positive = worth refining yourself, negative = buy the +N item from market.

⏱ MVP Tracker

Coordinate MVP hunting with a group: who killed what, when does it respawn, who's holding which drops, who owes who.

Sign in

1
Click 🔑 Sign In on the top bar. You'll be asked to authorise with Discord. Your Discord username is used as the in-tracker identity.
2
On first sign-in, set your character name — it shows up in payment splits and loot rows.

Groups

A group is a party that hunts together. All kills, loot and payments are scoped to a group.

  • Create a group from the Groups tab; it gets an invite code.
  • Join a group by pasting that code.
  • You can be in multiple groups; switch from the Groups tab.
  • Want to use the tracker solo? Make a group with just yourself.

Registering a kill

1
Open the MVP card for the boss you killed and tap + Register kill.
2
Set the kill time (defaults to now). For known MVPs the next respawn window is computed automatically; for the Bio-3 / Bio-4 series you can override the respawn time via the Custom Respawn Time button.
3
Pick the party members present. Tick "Killed by others" if loot doesn't belong to the group (still tracks the spawn for timer purposes).
4
Drops: the modal pre-fills the boss's drop list ranked by drop rate. For each row, either confirm it dropped or tap "didn't drop". To add an off-list item, type its ID — the name is resolved from the items DB (ratemyserver first, divine-pride fallback) and cached.
5
Assign each drop to a holder (whoever picks it up). You can change this later from the Loot tab.
Item ID shortcut. If a drop name shows as Item #12345, the backend is offline. Restart it (see Backend & setup) and re-enter the ID — the name will be cached for next time.

Loot tab — sell, split, settle

  1. Each drop row shows a status chip: Sold / For Sale / Kept.
  2. The 💰 Mark Sold button is only visible to the player holding the item. Tap it, enter the sale price (with shorthand 5m, 500k), confirm.
  3. The Payments tab automatically computes who owes whom based on sold items + party composition at the time of each kill.
  4. The ↩ Undo button (next to the kill header) is for the original registerer only; it reverses a mis-registered kill including its loot rows.

Payments tab

Three things at a glance:

  • Estimated value of unsold items currently being held or listed for sale.
  • Zeny held per player — how much each member has collected from sold items and needs to pay out (or is owed).
  • Settlement list — "Player A → Player B: X z" rows. The math is already simplified, no chain transfers.

🤖 Discord bot

The bot watches a Discord channel and posts MVP spawn notifications to it; you can also register kills from Discord screenshots.

One-time setup

1
Invite the bot to your Discord server. The OAuth link is in bot_config.json's app page on the Discord Developer Portal — required scopes are bot and applications.commands, permission set Send Messages + Embed Links + Read Message History.
2
In the channel you want notifications in, run /link from the bot. The command links that Discord channel ID to your tracker group (only group admins can run it).
3
Optional: set a mention role with /mention <@role> — that role is pinged on every spawn notification so people get a phone alert. You can mute the channel for everything except role mentions.

What the bot does automatically

  • Every 60 seconds the backend checks each linked group for MVPs spawning within the next minute and posts a rich embed: MVP name, map, thumbnail, /navi warp command.
  • Spawn notifications include a 🔔 button so members can subscribe to private DM reminders for that specific MVP.
  • The bot tolerates clock skew — respawn windows are computed server-side, not from the Discord message timestamp.

Manual / slash commands

/link
Link this channel to your tracker group (admin only).
/unlink
Remove the link.
/mention @role
Set the role pinged on spawn alerts.
/navi <MVP>
Reply with the navi macro for that MVP map / coords.
🔔 Notify Discord
Button on every MVP card in the tracker — posts a "spawn imminent" embed on demand.
Security — rotate your tokens. bot_config.json holds the bot token + bot_secret in plaintext. It's not in .gitignore yet, so if the GitHub repo is public the secrets are exposed. Steps:
  1. Discord Developer Portal → your bot → Reset Token.
  2. Regenerate bot_secret (any 32-byte hex string).
  3. Move both to bot_config.local.json (loaded at runtime, gitignored).
  4. Commit a bot_config.example.json with placeholders.

⚙️ Backend & setup

The MVP Tracker needs the local PowerShell backend on port 9500. The Refine Calculator works fully offline.

Start the backend

  1. Right-click Start → Terminal (Admin) (must be Administrator to bind port 9500).
  2. Run: 
    cd B:\Coding\ro-calc
.\serve-backend.ps1
  3. Wait for "MVP Tracker backend running on http://localhost:9500".
  4. Open http://localhost:9500/mvp.

Restart after backend updates

powershell -ExecutionPolicy Bypass -File "B:\Coding\ro-calc\restart-backend.ps1"

Or close the terminal window and start fresh. To verify it's up, visit http://localhost:9500/api/auth/me — should return JSON.

🛟 Troubleshooting

SymptomFix
"Access is denied" on backend start Run PowerShell as Administrator.
Port 9500 already in use Another instance is running. netstat -ano | findstr :9500 to find the PID, then taskkill /F /PID <PID> (from Command Prompt as Admin).
App can't connect to backend Visit http://localhost:9500/api/auth/me. If it returns JSON the backend is up; if not, restart it.
"Item #12345" instead of a name Item-name lookup needs the backend running. Restart it and re-enter the item ID — name is cached after first resolution.
Undo kill says "Error: Not found" The DELETE endpoint was added recently. Restart the backend to pick it up.
Bot doesn't post spawn notifications Check the channel ID is set with /link and that the bot has Send / Embed permissions. Backend must be running.

💾 Data & backup

All persistent state lives in B:\Coding\ro-calc\mvp-tracker\data\:

  • users.json, sessions.json — auth.
  • groups.json — groups + members.
  • kills_{groupId}.json — registered kills per group.
  • items.json — shared item DB (names + last sold prices).
  • group_config_{groupId}.json — per-group settings (mention role, hidden drops, etc).

To back up:

Copy-Item "B:\Coding\ro-calc\mvp-tracker\data" `
  "B:\Backups\ro-data-$(Get-Date -Format yyyyMMdd)" -Recurse

Restoring is just the reverse — copy the data folder back. Backend must be stopped while you swap files.
